# Запуск backend

`.env` содержит локальные значения для Docker Compose. `.env.example` показывает имена переменных без значений. Для контейнера backend `DATABASE_URL` указывает на `db:5432`; порт PostgreSQL не публикуется на хосте, поэтому другой локальный проект может использовать `localhost:5432`. HTTP-порт backend задаётся `PORT`.

В этом локальном варианте PostgreSQL работает с `POSTGRES_HOST_AUTH_METHOD=trust`: пароль не требуется. Не используйте эту конфигурацию для сервера, доступного недоверенным клиентам. Режим аутентификации задаётся при первой инициализации тома PostgreSQL. Если том `postgres_data` уже создан с парольной аутентификацией, простая смена `.env` не меняет его настройки; потребуется вручную перенастроить существующую БД или создать новый том, сохранив нужные данные отдельно.

Запуск: `docker compose up --build`. Compose ждёт готовности PostgreSQL, затем запускает backend. При старте backend применяет встроенные SQL-миграции из `migrations/`; применённые версии записываются в `schema_migrations`. Новые миграции должны иметь имя `NNNNNN_*.up.sql`. Удалять или менять уже применённые миграции нельзя. Существующую БД, созданную вручную без `schema_migrations`, нужно сначала привести к учтённой версии миграций.

Локальный запуск: `go run ./cmd/server`. Приложение читает `.env` из текущего каталога; уже заданные переменные процесса имеют приоритет. Для запуска вне Compose укажите доступный с хоста адрес PostgreSQL в `DATABASE_URL`. `PORT`, `DATABASE_URL` и `JWT_SECRET` обязательны. `GET /health` проверяет соединение с БД: 200 при готовности, 503 при недоступности. HTTP-запросы и ошибки пишутся в JSON-логи без токенов и паролей. При SIGINT/SIGTERM сервер даёт активным HTTP-запросам до 10 секунд на завершение.
