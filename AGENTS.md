# Шахматное приложение: бэкенд

## Стек
- Go 1.22+, роутер: chi (или net/http)
- БД: PostgreSQL, доступ через pgx, миграции в `migrations/`
- Клиент: React Native (в каталоге `mobile/`, бэкенд его не трогает)

## Структура
- `cmd/server/` — точка входа
- `internal/handler/` — HTTP-хендлеры (только разбор запроса и ответ)
- `internal/service/` — бизнес-логика
- `internal/repository/` — работа с БД
- `internal/model/` — структуры данных


Зависимости идут в одну сторону: handler → service → repository.
Сервис и репозиторий описываются интерфейсами, чтобы их можно было подменять в тестах.
Интерфейс живет там, где он используется

## Команды
- Запуск: `go run ./cmd/server`
- Тесты: `go test ./...`
- Линтер: `golangci-lint run`
- Перед тем как считать задачу готовой, должны проходить и тесты, и линтер.

## Правила кода
- Ошибки оборачиваем: `fmt.Errorf("...: %w", err)`, не глотаем.
- `context.Context` первым аргументом во всех методах, которые ходят в БД.
- Пароли только в виде bcrypt-хеша, никогда не логируем пароли и токены.
- Секреты и настройки (JWT-секрет, DSN) берём из переменных окружения, в коде их нет.
- Таблицы тестов (table-driven) для логики сервисов.
- Формат ошибок API: `{"error": "текст"}` и корректные HTTP-коды.
